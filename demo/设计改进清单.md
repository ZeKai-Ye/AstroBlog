## 〇、结论

> 以下是修复前的判断；逐项现状见文末两节修复记录。

**底子是好的，别推翻。** 纸、宋体、朱红、留白、点线目录、实时日晷、"工作 / 生活"两版——这套语言是统一的，执行也细（`prefers-reduced-motion`、`:focus-visible`、shiki 双主题、字体子集、three.js 按需渲染）。下面的问题不是"风格不对"，而是**完成度**和**几个结构性决策**。

三个结构性缺口：

1. **主题开关同时在切颜色和换内容。** 读者点一下"生活"，整页内容被换掉；日落时还会自动发生。见 `P0-3`。
2. **小字号灰字在纸色底上低于可读阈值。** `--muted-soft` 在画布色上是 **2.98:1**，朱红 `--accent` 是 **3.72:1**，而它们承担了几乎所有的日期、分类、计数、说明。见 `P1-1`。
3. **手机端是缩小的桌面，不是设计过的手机端。** 页头常驻 **115px**（约 14% 屏高）、导航点击区 **34px**、标题出现"刻。"单字成行。见 `P1-2` / `P1-3`。

四个"读者会以为没做完"的地方：页头字标糊成一团（`P0-2`）、作者/页脚/联系方式/项目还是占位（`P0-1`）、正文里写着 `src/settings.json`（`P0-4`）、搜索页默认是空白（`P1-4`）。

视觉上最不统一的是**图像**：冷蓝天空照、蓝墨题图、彩色漫画、暖色 3D 桌面，被放在同一本"纸刊"里（`P1-5`）。

- 「关于」页：`hello@example.com`、`@your-handle`，下面还直接写着"以上信息均为占位内容，请替换为你自己的。" → `07-about.jpg`

#### P0-2 · 页头字标压到 40px 不可读，夜间还是一块亮米色 · M

**现象**

`webheader.webp` 是 960×181 的题图（蓝墨希腊文 + 风景照），在页头被限制为 `height: clamp(30px, 3vw, 40px)`，实际约 **213×40px**。结果：笔触糊成蓝色色块，照片里的太阳、人、牛变成脏点；夜间页头是深色，而这张图仍带米色底，成了一张**发光的贴纸**。→ `02-header-logo.jpg`、`10-night-hero.jpg`

**位置**

- `src/components/SiteHeader.astro:32-42`（`widths={[180, 240]}`、`sizes="180px"`）
- 同文件 `:130-140`（`height: clamp(30px, 3vw, 40px)`；夜间只有 `brightness(.98) saturate(.95)`）
- `src/settings.json:33` `images.logo`

**建议**（按成本从低到高）

1. **页头改用文字字标**：`brand__name` + `brand__sub` 已经写好了（`SiteHeader.astro:44-48`），把 `images.logo` 从页头拿掉，题图只留在「关于」页。
2. 或者裁一枚**专用小字标**：只取Ἔργα καὶ Ἡμέραι 的笔迹，透明底，高 24–28px，另做一份浅色版给夜间；`<picture>` 或 `[data-theme='night']` 切换。
3. 如果坚持用现在的题图，至少给它一个**纸色底板**（`padding` + `background: var(--paper)` + 1px 线），让它在深色页头里看起来是"贴在纸上"，而不是一块发光的图。

**验收**

- [ ] 1440 与 390 两档、日间与夜间，品牌都能读出（Ἔργα καὶ Ἡμέραι / Erga kai Hemerai）。
- [ ] 夜间页头没有高亮矩形色块。
- [ ] 关于页的题图仍按 960px 原尺寸展示（那里是合适的尺寸）。

#### P0-3 · 主题开关换掉整页内容，并可能在阅读中自动发生 · L

**现象**

`index.astro` 同时渲染了「工作版」和「生活版」两套内容，靠 `html[data-theme='night']` 的 `display` 切换（`index.astro:1500-1534`）。所以：

- 在首页 3200px 处（正在看「写下来的事」）点一下右上角的开关，**脚下那一节直接变成「此刻」**；页面高度从 5257 掉到 4534，滚动位置留在原地但内容已换人。
- 日落时 `site.ts` 的 `scheduleSolar()` 会自动调用 `transitionTo()`（`site.ts:301-320`），**读者可能正读着，页面自己换了版**。
- 副作用：手机端首屏内容、目录条数（5 项 / 4 项）、CTA 文案都跟着变；"工作 / 生活"看起来像主题，实际是版次。

这不是"实现 bug"，是一个需要你确认的**产品决策**。它很有个性，但代价是：读者无法同时看到两版、也无法预期点一下会发生什么。

**建议**（三选一，按你想要的叙事强度排序）

1. **主题只改颜色，版次单独做开关。** 把"工作 / 生活"从主题开关里拆出来，hero 里放一个明确的「工作版 / 生活版」切换（或者两版各占一个 URL：`/` 与 `/life/`），颜色跟随主题。这是最不意外、也最像"出版物"的做法。
2. **保留联动，但不要自动。** 主题仍跟太阳走；日落时**不换版**，只在页脚/页头出现一行提示："天黑了，要翻到生活版吗？" 由读者点。
3. **保留现状，但把名字改准。** 叫「版次」而不是「主题」，并在切换时给一个短暂的说明（"已翻到生活版"），同时把滚动位置恢复到对应章节。

**验收**

- [ ] 在任意滚动位置切换，读者不会被"传送到另一篇文章"；或者切换后明确告知去了哪里。
- [ ] 页面在读者无操作的情况下不会自己换内容（颜色可以跟太阳）。
- [ ] 两版都能被读者主动找到（不依赖当前时辰）。

### P1 影响阅读与使用

#### P1-1 · 小字对比度不足（2.98:1 / 3.72:1）· S

**现象**

纸色底（`--bg: #f0d9c7`）上，承担几乎所有元信息的小字低于 WCAG AA（4.5:1）（可对照 `01-hero-day.jpg` / `05-writing.jpg`）：

| 组合 | 比值 | 用在哪 |
| --- | --- | --- |
| `--muted-soft #8a7c6d` on `--bg` | **2.98** | 目录计数、标签计数、题图角标、预览日期、Colophon、图注 |
| `--muted-soft` on `--paper #fff1d4` | **3.62** | 题图说明、卡片注脚 |
| `--accent #a65a3c` on `--bg` | **3.72** | 日期、分类、序号、`#标签`、引用正文 |
| `--accent` on `--paper` | 4.53 | 勉强及格 |
| `--muted #6a5c4f` on `--bg` | 4.75 | 及格，可以托底 |
| `--rose #f29191` on `--paper` | 2.03 | 只适合做装饰（圆点、下划线） |

这些字号本身也小：`--fs-micro: 11px`，页脚 11.5px，日期/计数 11–13px，还叠了 0.15em 的字距。纸刊上的小字靠印刷精度，屏幕上靠对比度。

**位置**

`src/styles/global.css:30`（`--muted-soft`）、`:38`（`--accent`）；使用点见 `index.astro:806/1110/1199/1665/1671`、`blog/index.astro:207`、`about.astro:137/206`、`SearchBox.astro:65`、`AuthorCard.astro:104`、`Figure.astro:95`。

**建议**

- 新增一个**文本专用**朱红：`--accent-text: #8f4a2e`（在 `--bg` 上 4.85:1，在 `--paper` 上 5.89:1），只给 24px 以下的文字用；`--accent` 继续给大数字、圆点、装饰。
- `--muted-soft` 只留给 ≥18px 的字或非文本装饰；所有 11–13px 的说明改用 `--muted`（4.75:1）。
- 底部的 11px 可整体抬到 12px（`--fs-micro: 0.75rem`），字距从 0.15em 收到 0.08em 左右——中文在小字号下不需要那么大的字距。
- 点线目录的 `border-bottom` 可以从 34% 提到 45% 左右，让"目录"真正可读。

**验收**

- [ ] 所有正文级（<24px）文字对比度 ≥ 4.5:1；用 DevTools 取色或任意对比度工具抽查 5 处。
- [ ] 在 1440 宽的屏幕上不放大也能读清日期、分类、计数。

## 四、别改掉的东西

修上面这些时，下面这些是站点的价值，别顺手"现代化"掉：

- **纸 + 宋体 + 朱红**的调性，以及 `--bg / --paper / --sheet` 这三层纸的层次；夜间不是把纸刷黑，而是换成暖墨色（`--ink #d8d2c5` 对 `#0f100c` 是 12.7:1，很舒服）。
- **日晷读的是真时间**（`Asia/Shanghai` + suncalc），不是装饰圆环；这是全站最有说服力的细节。
- **点线目录、罗马数字、版本号、便签印章**这些"书"的小零件。
- **两版的文学性**：白天的"工作，与时日。"与夜里的"夜色、阅读与一些很小的日子"。概念本身很好，问题只在切换方式（P0-3）。
- **动效克制**：0.9–1.1s 的纸面上浮、2.4s 兜底、`prefers-reduced-motion` 降级、hover 才展开的细节。
- **可访问性基础**：`:focus-visible`、skip link、语义化结构、`aria-live` 的搜索状态、`aria-hidden` 的装饰层。
- **性能**：three.js 按视口懒加载、按需渲染；字体只下了 2 个 woff2（约 61KB）；首页没有 UI 框架。

## 五、三个更大的方向（不是逐项修补）

如果愿意再多走一步，这三个方向能把"好看的页面"变成"有主张的出版物"：

1. **把两版做成真正的"版次"，而不是主题。** 在首屏给一个明确的 `工作版 / 生活版` 切换（甚至两个 URL），颜色跟随时辰。读者既能看见两版，也不会被自动换页。P0-3 的根治方案。
2. **建立一套图版规范。** 一种比例、一种装裱、一层统一的暖色/夜间压暗、一句图注。它会把 3D、照片、漫画、题图拉到同一本刊里，成本比换素材低。P1-5 的根治方案。
3. **把"时间"收成一处读数。** 页头、日晷、一天已过、Now 卡片、页脚各读一次同一个时钟；做成一个 `<Now />` 组件，其他位置只做引用或删掉。首屏会更安静，日晷也更突出。P2-11 的根治方案。

## 九、P0-2 / P0-3 修复记录

### P0-3 · 版次与主题分开

- 新增 `html[data-edition="work|life"]`：两套首页内容由它决定，`data-theme` 只负责颜色。
- 右上角开关仍是"一个动作翻版 + 换灯"，但**只有读者点它才会换**：
  - 打开页面时按太阳决定先给哪一版；打开后**不再自动换版**（删掉了日落定时器，以及切回标签页时的自动切换）。
  - 在首页 3200px 处切换：先回到新版的封面（旧行为是脚下那节被换掉），滚动发生在转场遮罩下面。
  - 文章页切换只换颜色：不滚动、不换内容。
- 首帧只认**手动**保存的偏好；太阳写下的主题不再参与首帧，避免中午打开先闪一下昨晚的生活版。
- 开关文字改为「工作版 / 生活版」，`aria-pressed` 表示生活版；ClientRouter 跳页时同时携带
  `data-theme` 与 `data-edition`。
- `README` 的「跟随日升日落」一节改为「太阳决定开场」。

验收：

- [ ] 首页深处点开关 → 回到新版封面，滚动位置为 0。
- [ ] 不点开关时，页面不会自己换版（颜色也不再自动变）。
- [ ] 两版都能通过开关随时到达。
- [ ] 刷新后保留手动选择；没有手动选择时按当前时辰开场。
